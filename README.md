# Hide Notch

独立 macOS 菜单栏工具，版本 **0.4.0**。在壁纸顶部绘制黑色菜单栏区域，让屏幕凹口融入黑色背景；可独立设置壁纸顶部与底部的圆角过渡。

## 安装与打开

本地执行 `./scripts/package.sh` 后，打包输出位于 `dist/`：

- `Hide Notch.app`：可直接打开的应用。
- `Hide-Notch-0.4.0.dmg`：打开后将应用拖入 `Applications` 安装。
- `Hide-Notch-0.4.0.zip`：应用压缩包。

当前生成的包适用于 **Apple Silicon，macOS 13 及更新系统**。设置界面采用 SwiftUI 原生分组表单和系统控件，跟随 macOS 27 的外观与深浅色设置。应用使用本地开发签名，尚未配置 Apple Developer ID 签名与公证。

界面示例使用合成壁纸和虚拟屏幕：[浅色](docs/settings-light.png) · [深色](docs/settings-dark.png) · [小窗口](docs/settings-compact.png) · [关闭状态](docs/settings-off.png)。

应用常驻菜单栏，无 Dock 图标。设置窗口采用紧凑单列表单，不再提供图片预览。点击笔记本图标 → **设置…**；关闭设置窗口不会退出应用。再次从 Finder 打开应用也会显示现有设置窗口。

## 使用

1. 确保需要处理的每块屏幕当前使用 **PNG/JPEG 静态壁纸**，以便恢复。
2. 默认处理内置显示器；没有内置屏时处理系统主显示器。
3. 开启 **同时应用到副屏** 后，所有独立显示器都纳入应用范围。各屏保留自己的壁纸、比例和缩放；镜像副本不重复处理。
4. 在“显示器”分组选择壁纸所属显示器。“选择壁纸…”只为当前选中的屏幕换图，开启时自动生效、关闭时保存本次选择；“使用当前壁纸”取消这块屏幕尚未应用的选图。
5. **顶部圆角** 默认开启，位于黑色菜单栏下方；**底部圆角** 默认关闭，开启后屏幕左右下角也呈圆角。两者独立控制，共用 4–48 pt 半径，同时开启时四角统一。可额外加高黑条 0–24 pt。
6. “显示器”分组上方的 **Hide Notch** 总开关立即生效：开启应用下方设置，关闭撤销黑条和圆角、还原原来的显示选项。关闭时仍可保存和调整参数；开启后修改参数自动生效，连续调整停止 300 毫秒后统一更新，不再需要应用按钮。菜单栏提供相同开关。
7. Hide Notch 开启时，关闭副屏选项会自动恢复此前处理过的已连接副屏。离线副屏的恢复记录仍保留，重新连接后可以恢复。
8. 不再提供单独的恢复按钮。关闭总开关时，后来在系统里手动换的壁纸保持原样；离线或操作失败的屏幕仍保留记录和开启状态，并提示连接屏幕或排除错误后再次关闭。

退出应用保留已应用效果，重启后开关会继承已有记录，不自动修改桌面；旧版已应用效果也可直接通过开关关闭。手动选择的新壁纸来源与用于恢复的最初壁纸分别保存，因此重启后调整圆角不会换回旧图。0.1 版的单屏恢复记录可自动读取。

## 实现与边界

- 使用公开 `NSScreen` / `NSWorkspace` 接口，生成新图片，不覆写用户原始图片。
- 按每块屏幕的菜单栏高度、屏幕尺寸和缩放分别绘制。设置窗口不提供图片预览；只有实际应用时才生成效果壁纸。
- 黑色区域是壁纸内容，菜单和图标仍由 macOS 绘制。系统材质、透明度和外观可能影响菜单栏实际颜色。
- 只支持单帧 PNG/JPEG，不支持动态 HEIC、视频、轮播壁纸；应用前的原壁纸也需为受支持的静态图片。
- 生成壁纸采用居中铺满；原来使用居中或平铺时构图可能变化，恢复时还原原显示选项。
- 处理各屏幕的**当前桌面**，不自动同步所有 Spaces。系统自身的共享壁纸设置可能联动其他桌面。
- 在系统中更换静态壁纸后，开启状态下点击“使用当前壁纸”可重新生成效果，并以新壁纸及其显示选项替换该屏幕的恢复记录；之后恢复到本次应用前的新壁纸。关闭总开关时不会覆盖用户后来换的图片。
- 无法区分系统换图与切换到不同壁纸的 Space；在新桌面主动调整设置或使用当前壁纸同样会更新该显示器的恢复基准，不保留每个 Space 的独立恢复记录。
- 多屏应用前先完成所有屏幕的检查和图片生成，预检查失败时不修改任何屏幕。系统提交期间若部分失败，会明确报告并保留所有恢复记录。
- 恢复时逐屏处理：某屏失败不会阻止其他屏幕恢复。断开的屏幕恢复记录保留。
- 不处理锁屏、全屏应用或系统动画；不要求录屏、辅助功能或管理员权限。

改名保留原有 Bundle ID `local.notchhide.app` 和偏好域，旧设置与恢复记录无需迁移。数据仍保存在 `~/Library/Application Support/NotchHide/`，其中 `restore.json` 记录各显示器的原图片地址、显示选项和选图来源，不复制原始文件。请保留原图片在原位置。已经交给系统的生成图片不自动清理，避免其他桌面仍引用；卸载前连接所有相关屏幕并关闭总开关，再删除应用与该数据目录。

## 开发、验证与打包

需要 Swift 6 与 Command Line Tools，无第三方依赖。

```bash
./scripts/run.sh                 # 构建并打开应用
./scripts/test.sh                # 图像与虚拟多屏测试，不修改系统壁纸
./scripts/preview-ui.sh          # 使用合成图片生成设置页布局快照
./scripts/package.sh             # Release 应用、DMG、ZIP
```

受限开发环境无法使用 SwiftPM 嵌套沙盒时，可运行：

```bash
NOTCH_HIDE_DISABLE_SPM_SANDBOX=1 ./scripts/package.sh
```

此开关只影响 SwiftPM 的构建沙盒，不改变应用权限。图标已包含在 `Configuration/AppIcon.icns`；可通过 `scripts/make-icon.swift` 生成 PNG 图标集，再使用 `iconutil` 更新。

验证包括 **6 项图像测试、10 项多屏/恢复测试、8 项总开关/自动更新测试**，以及深色、浅色和 440×560 小窗口的布局快照。多屏系统写入使用模拟后端验证，未自动更换用户的真实壁纸，真实外接显示器效果仍需实机确认。

## 源码结构

- `App.swift`：菜单栏、设置窗口、屏幕/桌面变化监听。
- `SettingsView.swift` / `SettingsModel.swift`：原生分组设置、每屏选图与偏好。
- `DesktopBackend.swift`：显示器信息与系统壁纸读写。
- `WallpaperService.swift`：多屏生成、逐屏恢复和旧版记录兼容。
- `WallpaperRenderer.swift`：图片读取、黑条和上下圆角绘制。
- `Tests/`：像素验证、虚拟多屏和设置页快照。
